# 輕量級自適應蜜碼防禦系統

# Lightweight_Adaptive_Honeywords_Defense_System

本專案為科展研究專案，目標是建立一套低算力、低成本、具備動態調整能力的密碼防禦系統，並除了防禦傳統攻擊模式，針對自動化撞庫攻擊等情境進行研究。
本研究不使用 AI 模型，而是透過 Honeywords、密/蜜碼距離分析、動態回饋、行為統計與隨機參數等方式，嘗試在系統負擔、使用者體驗與防禦效果之間取得平衡。
## 研究動機
現有的帳號防禦機制，例如帳號鎖定、驗證碼等方法，在面對大量自動化登入時，可能增加系統維護成本，也可能影響正常使用者的登入體驗。
對於缺乏大量資安資源的中小型企業或低算力設備而言，如何在有限的計算資源下提供有效的防禦，是值得探討的問題。
因此，本研究希望建立一套：
低計算成本
低維護成本
可動態調整
能辨識可疑登入行為
能降低正常使用者誤判
的密碼防禦系統。
## 核心概念
### Honeywords
Honeywords（蜜碼）是與真實密碼一起儲存的假密碼。
系統並不只保存一組可供登入判斷的密碼，而是配置多組誘餌密碼。
當有人嘗試使用 Honeyword 登入時，系統可以將這個事件視為可疑訊號，進一步啟動防禦機制。
本研究主要探討：
如何產生「不容易被攻擊者辨識，同時又不容易被正常使用者誤觸」的 Honeywords？
## Honeyword 甜度悖論
Honeywords 的重要問題之一是「甜度悖論」。
如果 Honeyword 與真密碼過於相似：
真人輸入錯誤
        ↓
誤觸 Honeyword
        ↓
系統產生誤判
但如果 Honeyword 與真密碼差異過大：
Honeyword 過於不自然
        ↓
攻擊者容易辨識
        ↓
Honeyword 防禦效果下降
因此，本研究希望尋找適當的距離，使 Honeywords：
對人的輸入習慣來說夠遠，對統計特徵來說又夠像。
## 密碼距離分析
Levenshtein Distance
本研究使用 Levenshtein Distance 分析密碼之間的字串差異。
Levenshtein Distance 計算將一個字串轉換成另一個字串所需要的最少：
Insert
Delete
Substitute
次數。
例如：
password
passw0rd
兩者只有部分字元不同，因此具有較小的 Levenshtein Distance。
本研究將此距離作為 Honeywords 生成與密碼相似度分析的其中一項參數。
Keyboard Distance
除了字串本身的差異之外，本研究也考慮使用者實際輸入密碼時的鍵盤空間關係。
例如：
Q W E R T Y
 A S D F G
  Z X C V
某些密碼雖然在字串上看起來差異較大，但可能由鍵盤上的相鄰按鍵構成。
因此，本研究將考慮：
鍵盤相鄰位置
鍵盤網格距離
Shift / Caps 等輸入因素
不同輸入設備（如手機螢幕等）的網格特徵
並與 Levenshtein Distance 進行比較。
## 多源 Honeywords 生成
本研究預計從多種來源建立 Honeywords 與測試資料：
外洩密碼資料
參考大型公開外洩密碼資料，用於分析常見密碼結構與測試系統。
密碼變異規則
參考 Hashcat 等工具所使用的密碼變異規則，分析攻擊者可能採用的密碼變形方式。
## 台灣在地化密碼習慣
透過問卷調查使用者的密碼結構與輸入習慣。
問卷不要求填寫真實完整密碼，而是針對密碼結構、排列方式等資訊進行調查。
這些資料將用於研究密碼模式，而非蒐集個人真實密碼。
## 動態防禦系統
本研究不採用單一固定的「錯誤 X 次後鎖定」規則，而是讓系統根據登入過程中持續取得的資訊動態調整防禦強度。
基本概念：
登入
 │
 ▼
密碼驗證
 │
 ├── 正常
 │
 └── 異常
      │
      ▼
  行為分析
      │
      ▼
 動態風險判定
      │
      ├── 一般錯誤
      │
      └── Honeyword
             │
             ▼
       提高防禦強度
## 三元判定
系統設計中加入：
Yes
No
Not Sure
三元判定概念。
在測試階段，可以使用較明確的 Yes / No 標記攻擊情況；在實際環境中，則保留 Not Sure 狀態，以處理無法完全確定是否為攻擊的情況。
這可以避免系統被迫對所有行為做出絕對判斷。
## 分層記憶與動態調整
系統會針對不同來源與帳號記錄登入狀態，例如：
IP
帳號
登入失敗次數
Honeyword 觸發次數
請求頻率
時間差
並透過分層記憶與自動清除機制，避免長期累積大量歷史資料造成額外負擔。
## 多 IP 撞庫攻擊
單純以 IP 判斷攻擊行為，在面對分散式撞庫攻擊時可能受到限制。
因此，本研究進一步考慮：
IP 1 ─┐
IP 2 ─┤
IP 3 ─┼──> ASN / 網路區域統計
IP 4 ─┤
IP 5 ─┘
              │
              ▼
        區域失敗率分析
              │
              ▼
        動態防禦調整
藉此研究在攻擊來源分散至多個 IP 時，是否仍能透過較高層級的統計資訊辨識異常流量。
## 隨機化防禦參數
如果防禦規則永遠固定，攻擊者可能透過大量試探逐漸推測系統規則。
因此，本研究考慮在部分動態參數中加入隨機數，使防禦行為不完全固定。
目標是在不大幅增加計算成本的情況下，提高攻擊者反推防禦規則的難度。
## 攻防實驗
本研究採用「紅、藍、綠」三方模擬架構。
### 🔴 Red Team — 攻擊模擬
模擬攻擊者可能採用的策略，包括：
外洩密碼資料
密碼變異規則
常見密碼結構
台灣在地化密碼結構
隨機攻擊策略
Credential Stuffing
測試不同攻擊策略下的系統反應。
### 🔵 Blue Team — 防禦系統
防禦系統負責：
Honeywords
Levenshtein Distance
Keyboard Distance
行為統計
動態回饋
延遲
暫時封鎖
管理員通報
並比較不同參數組合的防禦效果。
### 🟢 Green Team — 真實使用者模擬
綠隊主要模擬正常使用者可能產生的行為，例如：
正常登入
偶爾輸入錯誤
多次輸入錯誤
不小心觸發 Honeyword
藉此測量防禦系統是否會對正常使用者造成過高的誤判。

## 系統架構
目前預計採用解耦式 API 架構。
主系統負責一般使用者驗證，而 Honey Checker 則作為獨立的防禦模組。
這樣的設計可以讓防禦機制與主要驗證系統解耦，方便後續測試、替換與模組化。

Security & Data Ethics
本專案為資安研究用途。
研究過程中：
不要求使用者提供真實完整密碼。
不將真實個人密碼作為問卷資料。
不在公開 Repository 中儲存真實使用者憑證。
外洩密碼資料僅作為研究與測試用途。
公開版本將避免提交不必要的敏感資料。
大型外洩資料集不直接存放於本 Repository；相關資料來源、使用方式與測試資料將另外說明。
Research Direction
本研究最終希望回答的核心問題是：
在不依賴 AI、低算力與低成本的條件下，是否能透過 Honeywords、密碼距離分析與動態回饋，建立一套具有實際防禦價值的自適應密碼防禦系統？
本專案將透過實驗數據，而非單純理論推測，評估不同防禦策略的實際效果。
本專案為學術與科展研究用途，其中的攻擊模擬、外洩密碼資料分析與防禦機制，皆應在合法的測試環境中使用。
